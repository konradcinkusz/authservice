Auth, handled. Once.

A standalone JWT authentication and authorization microservice for ASP.NET Core. User accounts, OAuth social login, multi-tenant organizations, and an admin API — run your own instance, point any frontend or backend at it over HTTP, and never build a login flow again.

What's inside

Accounts & JWT

Registration, login, password reset/change, lockout, soft-delete with a retention period. Short-lived access tokens plus long-lived, server-side revocable refresh tokens.

OAuth social login

Google and GitHub out of the box — enabled automatically once credentials are configured, and harmless to leave unset otherwise.

Organizations

Multi-tenant grouping with Owner / Admin / Member roles, email invitations with retry tracking, soft-delete and restore.

Admin API

Paginated user and organization listing, role management, account lockout and restore — protected by Admin/SuperAdmin roles.

Consent tracking

Versioned Terms / Privacy / Cookies acceptance records for GDPR-style accountability.

Bring your own database

PostgreSQL by default, or SQL Server — selected by configuration, not by fork. Rate limiting, CORS, and Swagger with JWT bearer auth are already wired in.

How it's meant to be used

One codebase, many independent instances. This isn't a shared, central identity server — every project that adopts authservice deploys its own copy: its own Fly app, its own database, its own signing key. Upgrading is a deliberate choice each project makes on its own schedule, not something that happens to you.

No source coupling. Every tagged release publishes a version-pinned image to ghcr.io/konradcinkusz/authservice. Consuming projects pull a specific tag and run it — the same relationship as pulling postgres:16-alpine, just an image this repo happens to publish instead of a public one.

Downstream services validate the JWTs this instance issues directly — organization membership and role travel as claims — without calling back into authservice on every request.
